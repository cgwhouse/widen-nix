# widen-nix

My NixOS system configuration. Built on Flakes + Home Manager, themed with Catppuccin (mocha + green) across both scopes, currently targeting a single QEMU VM (`widen-nix-vm`) with room to grow to more hosts.

## Layout

```text
flake.nix              # Inputs, mkHost, nixosConfigurations
flake.lock

hosts/<name>/          # Per-host: hardware, hostname, stateVersion, hw-specific knobs
  default.nix
  hardware.nix         # Auto-generated by nixos-generate-config
  ...                  # Anything else only this host needs (e.g. vm-guest.nix)

modules/nixos/         # Shared NixOS config. Every host imports the whole directory.
  default.nix          # Imports every sibling .nix
  <feature>.nix        # One file per feature (audio, fonts, firmware, ...)

home/cristian/         # Home Manager config for my user (same on every host).
  default.nix          # Imports every sibling .nix
  <feature>.nix

secrets/               # agenix-encrypted secrets + the recipient list
  secrets.nix
  *.age
```

**Layout principle: feature-first, not service-first.** When a feature spans both scopes (e.g. Catppuccin theming touches HM via plasma-manager and NixOS via the SDDM module), it lives in mirrored files (`home/cristian/catppuccin.nix` and `modules/nixos/catppuccin.nix`) rather than being threaded into the nearest existing service module.

## Inputs

| Input | Why |
| --- | --- |
| `nixpkgs` (unstable) | The package set. Tracking unstable for fresher packages on a personal machine. |
| `home-manager` | User-scope config (dotfiles, per-user packages). |
| `plasma-manager` | Declarative KDE Plasma settings (themes, shortcuts, defaults). |
| `catppuccin` | Cross-scope theming for SDDM, Plasma, terminal apps, editors. |
| `agenix` | Age-encrypted secrets, decrypted into `/run/agenix/*` at activation. |

All non-nixpkgs inputs use `inputs.nixpkgs.follows = "nixpkgs"` to dedupe the package set.

## Rebuild / test loop

On the target NixOS machine, from the repo root:

```sh
# Pull latest
git pull

# Dry build (no activation) — catches eval and build errors
sudo nixos-rebuild build --flake .#widen-nix-vm

# Build + switch
sudo nh os switch .

# Misc
nix flake update      # bump all inputs
nix flake check       # eval check
nixfmt-tree           # format every .nix file in the tree
nh clean all          # garbage-collect old generations + roots
```

Convenience aliases in [`home/cristian/zsh.nix`](home/cristian/zsh.nix): `pkgup` (`nh os switch .`), `pkgsy` (`nix flake update`), `pkgcl` (`nh clean all`).

## Adding a new host

**1. Install NixOS** on the target and copy the generated hardware config:

```sh
nixos-generate-config --root /mnt --show-hardware-config > hosts/<name>/hardware.nix
```

**2. Create `hosts/<name>/default.nix`** mirroring [`hosts/vm/default.nix`](hosts/vm/default.nix):

- Import `./hardware.nix` and `../../modules/nixos`.
- Set `networking.hostName` and `system.stateVersion`.
- Add hardware-specific knobs that don't belong in shared modules:
  - **Microcode** — `hardware.cpu.amd.updateMicrocode = true;` or `hardware.cpu.intel.updateMicrocode = true;`.
  - **GPU** — e.g. `hardware.graphics.enable = true;` plus driver-specific options.
  - **Laptops** — `services.power-profiles-daemon.enable` or `services.tlp.enable`, backlight, suspend tweaks.

**3. Register the host** in [`flake.nix`](flake.nix) under `nixosConfigurations`:

```nix
nixosConfigurations = {
  widen-nix-vm = mkHost "vm";
  <name>       = mkHost "<name>";
};
```

**4. Build it.**

If a shared module ever needs to be opt-in per host (e.g. `desktop.nix` doesn't make sense on a headless box), introduce a `widen.<feature>.enable` option in that module and gate the config on it. Don't pre-build the options system before you have two hosts that disagree.

## Secrets (agenix)

No secrets are committed yet — the scaffolding exists so the first one is trivial.

**One-time setup:**

1. Put your user public key (`~/.ssh/id_ed25519.pub`) and each host's public key into [`secrets/secrets.nix`](secrets/secrets.nix). Host keys are auto-generated on first boot; grab them with `ssh-keyscan -t ed25519 <host>`.

**Per-secret flow:**

```sh
cd secrets
agenix -e mysecret.age      # opens $EDITOR; encrypts on save
```

Reference it from a module:

```nix
age.secrets.mysecret.file = ../../secrets/mysecret.age;
# Decrypted at /run/agenix/mysecret
# Owner/mode/path are configurable on age.secrets.<name>.{owner,mode,path}
```

The recipient list in [`secrets/secrets.nix`](secrets/secrets.nix) controls which keys can decrypt which files — adding a new host means re-running `agenix -r` to rewrap existing secrets to include its key.

## Themes

Catppuccin mocha + green, applied via:

- [`home/cristian/catppuccin.nix`](home/cristian/catppuccin.nix) — global `catppuccin.enable = true` in HM scope, which auto-themes Ghostty, Neovim, Firefox, Starship, and friends. Also installs the Plasma global-theme + cursor packages.
- [`modules/nixos/catppuccin.nix`](modules/nixos/catppuccin.nix) — SDDM login screen.
- [`modules/nixos/plymouth.nix`](modules/nixos/plymouth.nix) — boot splash.
- [`home/cristian/vscode.nix`](home/cristian/vscode.nix) — VS Code workbench + icon theme.
- [`home/cristian/plasma.nix`](home/cristian/plasma.nix) — Plasma look-and-feel + cursor.
